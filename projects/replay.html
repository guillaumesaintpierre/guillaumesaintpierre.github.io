MY ROLE

Machine Learning engineering: feature pipeline integration, testing and tactical event retrieval

EPFL AI Team is a student engineering association that develops applied AI projects in multidisciplinary teams. Within REPLAY, I work on the machine-learning side of a football analysis platform designed to make video and player tracking useful to coaches and analysts.

ENGINEERING NOTE 01

01 — Why football analysts need more than detection

Raw broadcast or panoramic footage is difficult to search. A coach may want the moments when a defensive block drops, a team stretches, a turnover occurs under pressure or a pattern repeats across several minutes. REPLAY aims to connect such questions to timestamped, inspectable match situations.

The project divides engineering responsibilities into two connected teams: computer vision turns video into player detections, identities, pitch geometry and structured temporal tracks; machine learning validates and interprets those tracks, extracts tactical features and resolves search requests. This is a team product rather than a one-person application.

ENGINEERING NOTE 02

02 — Computer vision inputs and reliability

The CV team investigated robust goal detection, player detection, re-identification, tracking and pitch boundaries. One weekly meeting reported goal detections in 739 of 741 frames for its specific clip, up from 283, after filtering implausible shapes and improving temporal persistence. Off-field person filtering uses foot-point location relative to pitch lines, with 15-frame temporal smoothing.

These are CV-team findings on particular runs, not global detection-accuracy claims. A different GPU-run screenshot illustrates a successful detection → re-identification → tracking chain, while pitch coordinate calibration, role assignment and ball tracking still required further validation at that snapshot.

ENGINEERING NOTE 03

03 — My work: the ML feature and query layers

My role centers on building and integrating reusable Python components that transform time-indexed player and ball data into interpretable tactical concepts. This includes team-shape metrics, player–ball proximity, pressure, possession, turnovers and temporal pattern detection; standardising structured queries; merging parallel feature implementations; and running regression tests on the combined pipeline.

In the meeting update our ML work was described as unifying existing features into one shared GitHub pipeline, resolving merge conflicts and validating feature modules. The goal is for a coach’s question to be converted into a structured specification, checked against supported parameters and run by deterministic feature engines — with matching clips retrieved by timestamps.

ENGINEERING NOTE 04

04 — Testing, failure analysis and boundaries

Meeting results came from different datasets and checkouts. One Claude Haiku snapshot reported 119/120 agreement on a 120-question benchmark and 33/35 on a newer 35-question benchmark; the same slide showed 35/35 schema-valid API responses and a 994-test offline regression run. These are not comparable accuracy measures and not proof of on-pitch tactical correctness.

A separate local qwen3:4b evaluation reported 12/19 exact query matches. Failure cases included invented duration values, mismatched tracking-ID types and unjustified player-identity assumptions. The practical lesson is that valid JSON is not enough: queries need grounding in source evidence and conservative handling of uncertainty.

The CV-to-ML handoff could be syntactically valid while still missing usable metric pitch coordinates, team IDs or ball observations. Consequently, the system must distinguish schema correctness from whether its underlying football evidence is adequate.

ENGINEERING NOTE 05

05 — Product perspective and attribution

Coach feedback recorded in the team slides motivated a broader objective than clip retrieval alone: the system should help prepare matches through zones, profiles, momentum and opponent-specific patterns. Those capabilities remain the broader product direction, not all demonstrated outcomes.
